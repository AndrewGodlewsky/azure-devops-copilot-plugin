# UI Polish Implementation Plan

> Execute inline with the executing-plans skill, followed by one independent review.

**Goal:** Make daily Azure Boards work easier to scan and act on without changing features or section order.

**Architecture:** Refine the existing theme-aware CSS and native DOM components. Use a native details disclosure for board movement; keep the existing mutation, focus and draft logic.

**Tech stack:** Native CSS/DOM, Node tests/JSDOM, Brave/Playwright smoke fixtures.

**Spec:** The user approved the focused Unslop direction on 2026-11-14: existing colors, system font and vertical navigation; consistent 36px navigation rows and controls, 14px body text, quieter borders, one emphasized action per view, compact Move controls and a less bulky task review. Keep all features and section order.

## Direction and audit

- Product: assigned ADO work beside the current Copilot conversation.
- Character: calm, precise, focused. World: a developer's workbench.
- Moments: selected work and its story/task hierarchy.
- Signature: consistent item IDs and meaningful state markers.
- Findings: oversized/inconsistent navigation, duplicate bright creation actions,
  small metadata, uneven spacing/radii, equally prominent section borders,
  permanent Move forms and tall repeated task-review fields.
- Approach: focused polish chosen over a full redesign. Preserve the palette,
  font, layouts and capabilities. No dependencies, decorative imagery or new features.
- Method: Unslop by Damir Sokolovsky (@heydamir), CC BY 4.0,
  https://heydamir.design/unslop. Preserve this credit in adaptations of this audit.

## Review focus

- Keyboard and touch can open Move; rerenders preserve open controls and focus.
- Failed moves retain rollback and errors; drag-and-drop still works.
- Text/controls wrap at 390px and inside narrow canvas containers.
- Existing host light/dark theme variables and focus indicators remain supported.
- Proposal and work-item edits survive presentation changes and rerenders.
